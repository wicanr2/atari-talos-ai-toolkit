# 008 — Motorola 68000 BSR

狀態：**CONFORMED**（2026-09-05）。

## 平台規格證據

- Motorola／NXP《M68000 Family Programmer's Reference Manual》，
  <https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf>，SHA-256
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- BSR 見手冊 4-59～4-60：先將 instruction 後的 PC long 推入 stack，再以
  instruction word 位址加 2 為基準套用 signed displacement。
- 68000 支援 byte 位移，以及 opcode 低 byte 為 0 時的 16-bit extension；不採用
  68020 才有的 32-bit displacement。

## 外部單步證據與範圍

- 使用 spec 003 固定的 `SingleStepTests/m68000` commit 與 `BSR.json.bin` 2,500 筆。
- 1,229 筆為偶數目標正常呼叫；1,271 筆為奇數目標並接續 spec 007 address error。
- 全語料確認 byte／word return PC、USP／SSP 選擇、stack write 次序、target、預取、
  address-error saved PC 與 clocks。

## 行為

1. 目標位址基準與 Bcc 相同：初始 next-prefetch PC 減 2，再加 signed byte／word 位移。
2. byte BSR 的 return PC 是基準位址；word BSR 的 return PC 是初始 next-prefetch PC，
   因為 16-bit extension 也屬於 instruction。
3. 依執行前 S bit 選擇 USP（FC 1）或 SSP（FC 5），先減 4，再依 high word、low word
   次序寫入 return PC。
4. 偶數目標以原模式 program FC 讀取兩格預取；最終 PC 為目標加 4，總計 18 clocks。
5. 奇數目標保留已推入的 return PC，再進入 spec 007。address-error frame 的 saved PC
   是 fault target 本身；user mode 的 USP 保留減 4 結果並改用 SSP 疊 frame，supervisor
   mode 則在已減 4 的 SSP 再減 14。整體為 68 clocks。
6. D0–D7、A0–A6 與 condition codes 不因 BSR 本身改變。

## 驗收

逐筆比較 2,500 筆完整 CPU 狀態、RAM、總 clock 與 bus transaction；正常與例外案例
必須在同一次完整語料執行中全數通過，才能升為 **CONFORMED**。

2026-09-05 驗收結果：1,229 筆正常呼叫與 1,271 筆 address error 全部通過。

## 停止線

- stack write、目標讀取或例外處理本身的 bus fault／double fault 不在本規格內。
- 不納入 68020 32-bit displacement。
