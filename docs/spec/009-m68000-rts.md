# 009 — Motorola 68000 RTS

狀態：**CONFORMED**（2026-09-05）。

## 平台規格證據

- Motorola／NXP《M68000 Family Programmer's Reference Manual》，
  <https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf>，SHA-256
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- RTS 見手冊 4-169：`(SP) → PC; SP + 4 → SP`，condition codes 不變；opcode `0x4E75`。

## 外部單步證據與範圍

- 使用 spec 003 固定的 `SingleStepTests/m68000` commit 與 `RTS.json.bin` 2,500 筆。
- 1,263 筆為偶數 return PC；1,237 筆為奇數 return PC 並接續 spec 007 address error。
- 語料確認 active stack、兩次 word read、SP 更新時點、預取、例外 saved PC 與 clocks。

## 行為

1. 依執行前 S bit 選擇 USP（FC 1）或 SSP（FC 5），從 SP 與 SP+2 依序讀取 PC high／low，
   再將該 stack pointer 加 4。
2. 偶數 return PC 以原模式 program FC 從 return PC 與 return PC+2 建立預取；最終 PC
   為 return PC+4，總計 16 clocks。
3. 奇數 return PC 保留已完成的兩次 stack read 與 SP+4，再進入 spec 007。frame 的
   access address 是 return PC，saved PC 是初始 next-prefetch PC 減 2，總計 66 clocks。
4. user mode 的 USP 保留加 4 結果，address-error frame 使用 SSP；supervisor mode 則從
   已加 4 的 SSP 再減 14，因此相對原 SSP 淨減 10。
5. D0–D7、A0–A6 與 condition codes 不因 RTS 本身改變。

## 驗收

逐筆比較 2,500 筆完整 CPU 狀態、RAM、總 clock 與 bus transaction；正常與例外案例
必須在同一次完整語料執行中全數通過，才能升為 **CONFORMED**。

2026-09-05 驗收結果：1,263 筆正常 return 與 1,237 筆 address error 全部通過。

## 停止線

- stack read、目標讀取或例外處理本身的 bus fault／double fault 不在本規格內。
