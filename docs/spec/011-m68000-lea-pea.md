# 011 — Motorola 68000 LEA／PEA

狀態：**CONFORMED**（2026-09-05）。

## 平台規格證據

- Motorola／NXP《M68000 Family Programmer's Reference Manual》，
  <https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf>，SHA-256
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- LEA 見手冊 4-110：effective address 寫入 An，不影響 condition codes。
- PEA 見手冊 4-153：SP 減 4，effective address long 寫入 stack，不影響 condition codes。
- control effective-address 計算沿用 CONFORMED spec 010。

## 外部單步證據與範圍

- 使用 spec 003 固定的 `SingleStepTests/m68000` commit；`LEA.json.bin` 與
  `PEA.json.bin` 各 2,500 筆，完整涵蓋七種 68000 control modes。
- ReDMCSB DM12EN 重建組語約含 LEA 1,124 次、PEA 554 次；數量只決定優先序，
  行為仍以官方規格與外部單步語料為準。
- 語料確認 extension 消耗、PC 推進、A7、index、stack FC、clock 與 bus 排程。

## LEA 行為

1. 依 spec 010 計算 effective address，寫入 opcode 指定的 An；目的為 A7 時依 S bit
   寫 USP／SSP。source A7 在目的寫入前取值。
2. 零 extension 消耗 4 clocks 並補一格預取；一般一-word extension 消耗 8 clocks；
   indexed one-word 與 absolute-long two-word 都為 12 clocks。
3. Dn、其他 An、SR 與 RAM 不變。

## PEA 行為

1. 先依 spec 010 計算 effective address，再依 S bit 選 USP（FC 1）或 SSP（FC 5），
   SP 減 4，依 high word、low word 推入 effective address。
2. clocks 為對應 LEA mode 加 8：12、16 或 20。
3. `(An)`、displacement 與 indexed modes 在完成該 mode 的預取後寫 stack。
4. absolute word／long 的 microcode 在最後一次預取前寫 stack；transaction 次序必須
   依語料保留，不能只比較最終 state。
5. Dn、A0–A6、SR 不變；只有 active stack pointer 與四個 stack bytes 改變。

## 驗收

兩份語料共 5,000 筆必須逐筆比較完整 CPU 狀態、RAM、總 clock 與 bus transaction；
全部通過後才能升為 **CONFORMED**。

2026-09-05 驗收結果：LEA 與 PEA 各 2,500 筆、合計 5,000 筆全部通過。

## 停止線

- 非 control mode 必須失敗即關閉。
- stack bus fault 與 address error 另立規格；本語料的 stack 都符合 word alignment。
