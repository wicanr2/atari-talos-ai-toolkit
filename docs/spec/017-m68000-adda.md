# 017 — Motorola 68000 ADDA.W／ADDA.L

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 `ADDA.W <source>,An` 與 `ADDA.L <source>,An` 的全部合法 data source
定址模式及 A0–A7 目的暫存器。輸入為 spec 003 固定的 `SingleStepTests/m68000`
commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

- `ADDA.w.json.bin`：正常 1,683、source read address error 817，共 2,500。
- `ADDA.l.json.bin`：正常 1,675、source read address error 825，共 2,500。

排除一般 ADD、ADDI、ADDQ、ADDX、bus error 及 exception handler 自身再 fault。

## 證據與等級

- **已確認（平台規格）**：Motorola／NXP《M68000 Family Programmer's Reference
  Manual》的 ADDA 指令定義；word source 先符號延伸至 32 bits，再與目的 An 相加；
  long source 直接作 32-bit 加法；condition codes 不受影響。
- 官方 PDF SHA-256：
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- **已確認（固定單步實驗）**：兩份語料逐筆提供完整 CPU state、RAM、clock 與 bus
  transaction；1,642 筆 odd source 另含 vector 3 的 14-byte frame。
- **已確認（Dungeon Master 使用範圍）**：ReDMCSB 產生的 DM12EN `OBJECT/ENGINE/FULL`
  組語共出現 `ADDA` 1,539 次、`ADDA.L` 18 次。這是編譯產物的靜態使用次數，只用來
  決定模擬器實作優先序，不宣稱等同執行期頻率。
  31 份 `.S` 依路徑排序後，逐檔 SHA-256 清單的 SHA-256 為
  `607feb2bc104af411d13e9909d9c57ffff626c3ef8737ec5cd765b22a7dafd46`。

## typed 行為

1. `ADDA.W` 取 16-bit source，依 bit 15 符號延伸成 32 bits 後與目的 An 相加；
   `ADDA.L` 以完整 32-bit source 相加。結果依 32 bits 回繞；A7 依當時 S bit 讀寫
   USP／SSP。
2. 正常與來源 fault 都不因 ADDA 更新 CCR。source EA、program／data FC、alignment、
   extension、prefetch、An predecrement／postincrement 副作用及 source address-error
   沿用已 CONFORMED 的 spec 014／015。
3. `ADDA.W` 正常 clocks 為 `8 + sourceCost`。`ADDA.L` 的記憶體 source 為
   `6 + sourceCost`，register direct 與 immediate source 為 `8 + sourceCost`；
   `sourceCost` 定義沿用 spec 014／015。
4. odd source 在讀取任何 operand word 前產生 `re`；SSW、saved PC、clock、frame、vector 3
   與 handler prefetch 沿用相應 word／long source 規格，不修改目的 An。

## 影響、驗收與停止線

- 只新增 ADDA decode 與 An 算術目的端，不改控制協定、Atari 素材或權利邊界。
- 逐筆比較兩份語料共 5,000 筆完整 state、RAM、clock、bus與 exception frame；既有
  42,500 筆不得回歸。
- 2026-09-05 驗收結果：ADDA.W 正常 1,683／1,683、`re` 817／817；ADDA.L
  正常 1,675／1,675、`re` 825／825，合計 5,000／5,000。全套外部單步語料累計
  47,500 筆全數通過。
