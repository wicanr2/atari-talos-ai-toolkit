# 018 — Motorola 68000 AND／ANDI

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 `AND.B/W/L <ea>,Dn`、`AND.B/W/L Dn,<memory>` 與
`ANDI.B/W/L #<data>,<ea>` 的全部合法 68000 data／alterable-memory 定址模式。
輸入為 spec 003 固定的 `SingleStepTests/m68000` commit
`64b253116a3de04aaac4346c43680960dc9b67e5`：

- `AND.b.json.bin`：AND `<ea>→Dn` 1,317、`Dn→memory` 1,007、ANDI 176。
- `AND.w.json.bin`：AND `<ea>→Dn` 1,333、`Dn→memory` 1,009、ANDI 158。
- `AND.l.json.bin`：AND `<ea>→Dn` 1,315、`Dn→memory` 1,056、ANDI 129。

排除 `ANDI to CCR`、`ANDI to SR`、bus error 及 exception handler 自身再 fault；
前兩項有獨立語料，未實作前維持失敗即關閉。

## typed 行為

1. 依 byte／word／long 寬度逐位 AND，窄寬度寫 Dn 時保留未參與的高位；記憶體目的端
   執行不可分割的讀改寫序列。
2. 正常完成後保留 X、依結果最高位與零值更新 N／Z，並清除 V／C。來源 EA、FC、
   extension、alignment、prefetch 及 address-error frame 沿用 spec 014／015。
3. 記憶體讀改寫的 bus 次序為 operand read、最後一次 program prefetch、operand write；
   long write 固定先 low word、再 high word。這與 MOVE.L 的一般寫回路徑不同。
4. word `(An)+` 在 odd-address fault 前保留 `An+2`；long `(An)+` 在同類 fault 不提交
   `An+4`。predecrement 在 fault 前提交遞減。這些副作用不得以單一泛型規則合併。
5. ANDI 先消耗 immediate，再解目的 EA；其正常與 fault clocks 包含 immediate 的
   byte／word 4 clocks 或 long 8 clocks 成本。

## 失敗模式、影響與驗收

- 不合法 destination、`ANDI to CCR/SR`、未實作 opcode 與 bus backend error 必須回傳錯誤，
  不得冒充成功。
- 不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。
- 三份語料共 7,500 筆逐筆比較完整 state、RAM、clock、bus 與 exception frame；既有
  47,500 筆不得回歸。
- 2026-09-05 驗收結果：7,500／7,500 全數通過；全套外部單步語料累計
  55,000 筆全數通過。
