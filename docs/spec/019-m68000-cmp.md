# 019 — Motorola 68000 CMP／CMPI／CMPM

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 `CMP.B/W/L <ea>,Dn`、`CMPI.B/W/L #<data>,<ea>` 與
`CMPM.B/W/L (Ay)+,(Ax)+`。輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

- `CMP.b.json.bin`：CMP 1,991、CMPI 233、CMPM 276。
- `CMP.w.json.bin`：CMP 2,032、CMPI 207、CMPM 261。
- `CMP.l.json.bin`：CMP 2,063、CMPI 190、CMPM 247。

排除 CMPA、bus error 及 exception handler 自身再 fault；CMPA 有獨立語料，未實作前
維持失敗即關閉。

## typed 行為

1. 依 byte／word／long 寬度計算 `destination-source`，不寫回運算結果；保留 X，並依
   結果更新 N／Z、依有號溢位更新 V、依無號借位更新 C。
2. CMP 的目的固定為 Dn；CMPI 先消耗 immediate，再讀 alterable-data 目的 EA。
   來源 EA、FC、extension、alignment、prefetch 與一般 address-error frame 沿用
   spec 014／015。
3. CMPM 依序讀 `(Ay)+` 來源再讀 `(Ax)+` 目的；兩個欄位指向同一 An 時，第二次讀取
   必須使用第一次後遞增後的位址。byte 的 A7 增量仍為 2。
4. CMPM word／long 的來源為奇位址時，來源 An 在 fault 前只提交 `An+2`；目的為奇位址
   時，目的 An 不提交增量。兩種情況的 vector-3 saved PC 都比一般 mode-3 source fault
   前進 2，必須使用 CMPM 專用微時序。
5. CMPI address error 的 clocks 必須包含已消耗 immediate 的 word 4 clocks 或 long
   8 clocks；CMPM 第二次讀取 fault 則包含第一次 operand read 的成本。

## 失敗模式、影響與驗收

- 不合法 EA、CMPA、未實作 opcode 與 bus backend error 必須回傳錯誤，不得冒充成功。
- 不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。
- 三份語料共 7,500 筆逐筆比較完整 state、RAM、clock、bus 與 exception frame；既有
  55,000 筆不得回歸。
- 2026-09-05 驗收結果：7,500／7,500 全數通過；全套外部單步語料累計
  62,500 筆全數通過。
