# 020 — Motorola 68000 ADD／ADDI／ADDQ

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 `ADD.B/W/L <ea>,Dn`、`ADD.B/W/L Dn,<memory>`、
`ADDI.B/W/L #<data>,<ea>` 與 `ADDQ.B/W/L #1..8,<ea>`。輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

- `ADD.b.json.bin`：一般 ADD 1,561、ADDI 116、ADDQ 823。
- `ADD.w.json.bin`：一般 ADD 1,538、ADDI 91、ADDQ 871。
- `ADD.l.json.bin`：一般 ADD 1,538、ADDI 90、ADDQ 872。

排除 ADDA、ADDX、bus error 及 exception handler 自身再 fault；ADDA 已由 spec 017
驗收，ADDX 有獨立語料，未實作前維持失敗即關閉。

## typed 行為

1. byte／word／long 都以目的加來源並依寬度回繞；窄寬度寫 Dn 時保留未參與的高位。
   結果更新 N／Z；同號相加得到異號時設 V；無號進位同時設 C 與 X。
2. ADD `<ea>→Dn` 讀取全部合法 data EA；`Dn→memory` 採 operand read、最後一次
   program prefetch、operand write 的讀改寫次序，long 固定先寫 low word 再寫 high word。
3. ADDI 先消耗 immediate，再解 alterable-data 目的 EA；其正常與 fault clocks 包含
   immediate byte／word 4 clocks或 long 8 clocks。
4. ADDQ 的 3-bit immediate 為零時代表 8。Dn long 比 byte／word 多 4 clocks；An
   destination 不受 encoded word／long 寬度影響，一律做 32-bit 加法、不改 CCR。
5. 記憶體 word／long 的 EA、FC、extension、alignment、postincrement／predecrement、
   prefetch 與 vector-3 frame 沿用 spec 018 已驗證的讀改寫路徑。

## 失敗模式、影響與驗收

- 不合法 EA、`ADDQ.B` 寫 An、ADDX、未實作 opcode 與 bus backend error必須回傳錯誤，
  不得冒充成功。
- 不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。
- 三份語料共 7,500 筆逐筆比較完整 state、RAM、clock、bus 與 exception frame；既有
  62,500 筆不得回歸。
- 2026-09-05 驗收結果：7,500／7,500 全數通過；全套外部單步語料累計
  70,000 筆全數通過。
