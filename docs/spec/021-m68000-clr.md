# 021 — Motorola 68000 CLR

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 `CLR.B/W/L <ea>`。輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

- `CLR.b.json.bin`：2,500 筆。
- `CLR.w.json.bin`：2,500 筆。
- `CLR.l.json.bin`：2,500 筆。

排除 bus error、例外處理器自身再次 fault 及 68010 以後處理器差異；不合法 EA 維持
失敗即關閉。

## 證據與等級

- **已確認（平台規格）**：Motorola／NXP《M68000 Family Programmer's Reference
  Manual》的 CLR 定義；目的值歸零，N／V／C 清除、Z 設定、X 不變。
- 官方 PDF SHA-256：
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- **已確認（固定單步實驗）**：三份語料逐筆提供完整 CPU state、RAM、clock 與 bus
  transaction；word／long odd operand 涵蓋 vector 3 的 14-byte frame。
- **已確認（Dungeon Master 使用範圍）**：ReDMCSB DM12EN 產生組語中，CLR.W
  858 次、CLR.B 64 次、CLR.L 80 次，合計 1,002 個靜態使用點。這只用於實作優先序，
  不宣稱等同執行期頻率。31 份 `.S` 依路徑排序後，逐檔 SHA-256 清單的 SHA-256 為
  `607feb2bc104af411d13e9909d9c57ffff626c3ef8737ec5cd765b22a7dafd46`。

## typed 行為

1. Dn 目的端依 byte／word／long 寬度清零，窄寬度保留未參與的高位；X 保留，
   N／V／C 清除，Z 設定。
2. 記憶體目的端遵循 MC68000 的讀改寫流程：先讀 operand、執行最後一次 program
   prefetch，再寫入零；long 固定先寫 low word、再寫 high word。
3. 全部 alterable-data EA 的 extension、FC、alignment、postincrement／predecrement、
   clocks 與 vector-3 frame 沿用 spec 018 已逐筆驗證的讀改寫路徑。

## 失敗模式、影響與驗收

- An direct、PC-relative、immediate、未實作 opcode 與 bus backend error 必須回傳錯誤，
  不得冒充成功。
- 不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。
- 三份語料共 7,500 筆逐筆比較完整 state、RAM、clock、bus 與 exception frame；既有
  70,000 筆不得回歸。
- 2026-09-05 驗收結果：7,500／7,500 全數通過；全套外部單步語料累計
  77,500 筆全數通過。
