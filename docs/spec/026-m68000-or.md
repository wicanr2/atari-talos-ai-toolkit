# 026 — Motorola 68000 OR／ORI

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

本規格涵蓋 MC68000 的 `OR.B/W/L <ea>,Dn`、`OR.B/W/L Dn,<ea>` 與
`ORI.B/W/L #<data>,<ea>`。輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

- `OR.b.json.bin`：2,500 筆。
- `OR.w.json.bin`：2,500 筆。
- `OR.l.json.bin`：2,500 筆。

`ORI` 至 CCR／SR 不在本切片；除零、SBCD 與不合法 EA 也不會因同屬 `0x8xxx`
編碼空間而誤接，未實作者維持失敗即關閉。

- 官方 PDF SHA-256：
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。

## typed 行為

1. 一般 OR 支援合法 data EA 至 Dn，以及 Dn 至可修改 memory EA；ORI 先依寬度讀取
   immediate，再寫入 Dn 或可修改 memory EA。
2. byte／word 目的 Dn 只覆寫低 8／16 位；long 覆寫全部 32 位。結果依寬度設定
   N／Z，清除 V／C，X 不變。
3. 記憶體目的端遵守 operand read → 最後一次 program prefetch → operand write；long
   寫回先 low word、再 high word。EA、FC、alignment、register side effect、clock 與
   vector-3 frame 沿用已驗證的讀改寫路徑。

## 失敗模式、影響與驗收

- An direct、PC-relative／immediate memory destination、ORI to CCR／SR、除法、SBCD、
  未實作 opcode 與 bus backend error 必須回傳錯誤，不得冒充成功。
- AND／ANDI、CLR 與 OR／ORI 共用已驗證的邏輯讀改寫骨架，但運算本身以明確分支選取，
  不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。
- 三份語料共 7,500 筆逐筆比較完整 state、RAM、clock、bus 與 exception frame；既有
  92,500 筆不得回歸。
- 2026-09-05 驗收結果：7,500／7,500 全數通過；全套外部單步語料累計
  100,000 筆全數通過。
