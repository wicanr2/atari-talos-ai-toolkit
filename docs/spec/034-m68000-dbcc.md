# 034 — Motorola 68000 DBcc

狀態：**CONFORMED**（2026-09-05）。

## 範圍與輸入

涵蓋 MC68000 全部 16 種 `DBcc.W Dn,<displacement>`。驗收輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：
`DBcc.json.bin` 共 2,500 筆。

Scc、TRAPcc 與後代 CPU 擴充不在本切片；不合法編碼失敗即關閉。

## 證據與 typed 行為

- **已確認（平台規格）**：Motorola／NXP《M68000 Family Programmer's Reference
  Manual》；官方 PDF SHA-256 為
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
- condition 成立時不改 Dn 且順序執行；condition 不成立時，只遞減 Dn 低 16 位。
- 遞減結果不是 `0xffff` 時，以 displacement word 位址為基準作 signed 16-bit 分支；
  結果為 `0xffff` 時終止迴圈並順序執行。所有路徑均不改 SR。
- 三條正常路徑分別為 condition 成立 12 clocks、計數到期 14 clocks、成功分支
  10 clocks。taken 奇數目標以計算出的目標為 fault address 進入 vector 3，但不提交
  Dn 遞減，exception frame 保存 extension 之後的順序 PC，總計 60 clocks。
- **已確認（DM 使用範圍）**：DM12EN 產生組語中 DBF 有 14 個靜態使用點；其他
  DBcc 條件未見。31 份 `.S` 雜湊清單 SHA-256 為
  `607feb2bc104af411d13e9909d9c57ffff626c3ef8737ec5cd765b22a7dafd46`。

## 失敗模式與驗收

非 Dn counter、缺少 displacement、TRAPcc、未實作 opcode 與 bus backend error 必須
回傳錯誤。不改 JSONL 控制協定、Atari 素材、存檔或權利邊界。固定語料逐筆比較
完整 state、RAM、clock、bus 與 exception frame；既有 152,500 筆不得回歸。
`DBcc.json.bin` 2,500 筆已全數通過；既有語料亦無回歸，故本規格升為 CONFORMED。
