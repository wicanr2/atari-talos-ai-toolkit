# 038 — Motorola 68000 DIVS／DIVU

狀態：**CONFORMED**（2026-09-05）。

## 範圍與證據

本規格涵蓋 `DIVU.W <ea>,Dn` 與 `DIVS.W <ea>,Dn` 的成功、16-bit quotient overflow、
word source address error 與 divisor=0 vector 5。依 Motorola／NXP《M68000 Family
Programmer's Reference Manual》，32-bit dividend 取自 Dn，16-bit divisor 取自 data EA；
成功時 Dn high word 為 remainder、low word 為 quotient。

## typed 行為

1. source EA 與既有 word data reader 共用，因此保留全部合法 EA、An side effect、
   program／data FC、extension prefetch 與 vector 3 address-error 微時序。
2. `DIVU` 使用 unsigned 32÷16；`DIVS` 使用 signed 32÷16，quotient 向零截斷，remainder
   與 dividend 同號。成功時 X 保留，以 low-word quotient 設 N/Z，V/C 清除。
3. quotient 超出 signed／unsigned 16-bit 時 Dn 不變，X 保留，N/V 設定且 Z/C 清除。
4. 迭代 clocks 不是固定常數：`DIVU` 依 restoring-division 每步比較／減法；`DIVS`
   依 dividend 符號、早期 magnitude overflow 與 absolute quotient bit pattern 計算。
   兩份語料逐筆驗證最終 clocks，EA cost 另加。
5. divisor=0 時先清 NZVC 再設 Z，Dn 不變；以當時 next-instruction PC 建立 format-0
   6-byte frame（SR、PC high、PC low），切 supervisor、清 trace，讀 vector 5
   `0x14/0x16` 並預取 handler。register source 共 40 clocks。
6. format-0 寫入次序由固定 TRAP 語料交叉確認：PC low、SR、PC high；frame 的記憶體
   排列仍是 SR、PC high、PC low。

## 驗收與停止線

- 5,000 筆逐筆比較完整 CPU state、RAM、clock 與 bus transaction。
- `internal/st` 以真實 memory backend 對 DIVU／DIVS 各驗一次 divisor=0 的 clocks、
  Dn、SR、SSP、完整 frame、vector fetch、handler PC 與 prefetch。
- vector fetch、stack write 或 handler prefetch 自身再 fault 的 double-fault／halt 行為
  尚未驗證，維持錯誤回傳；不得由本規格宣稱已完成整個 exception subsystem。
