# 039 — Motorola 68000 TRAP／RTE

狀態：**CONFORMED**（2026-09-05）。

## 範圍與證據

本規格涵蓋 `TRAP #0..#15`、supervisor-mode `RTE`、user-mode privilege violation，
以及 RTE 恢復奇數 PC 時的 vector 3。依 Motorola／NXP《M68000 Family Programmer's
Reference Manual》，TRAP 使用 vectors 32–47；RTE 只能在 supervisor mode 從
format-0 frame 恢復 SR 與 PC。

固定外部語料來自 `SingleStepTests/m68000` commit
`64b253116a3de04aaac4346c43680960dc9b67e5`：

| 語料 | 分母 | SHA-256 |
|---|---:|---|
| `TRAP.json.bin` | 2,500，全部 34 clocks | `fead4435111103b49ccdef17f60852c438d81f21f1fd9a5ffcac0c2548ad7a85` |
| `RTE.json.bin` | 正常 600、odd target 614、privilege 1,286 | `6f2de0d6abc51528ff62498af4e61b311102300f9f4d5fb825681116b3a0249c` |

DM12EN 重建組語集合雜湊見 spec 037；靜態盤點為 `TRAP` 8、`RTE` 6 個使用點。
它們是 Atari OS 呼叫與中斷返回的必要控制流；計數不等同執行期頻率。

## typed 行為

1. `TRAP #n` 保存 opcode 後的 PC，以原 SR 建立 6-byte frame，切 supervisor、清 trace，
   從 `(32+n)*4` 讀 handler 並預取兩個 words；固定 34 clocks。
2. format-0 frame 的記憶體排列是 SR、PC high、PC low；MC68000 bus 寫入次序是 PC low、
   SR、PC high。user-mode TRAP 寫 supervisor stack，USP 不變。
3. user mode 執行 RTE 不讀 user stack，直接以目前指令 PC 進 privilege violation vector 8，
   建立相同 format-0 frame；固定 34 clocks。
4. supervisor RTE 依序從 SSP 讀 SR、PC high、PC low，SSP 提交 `+6`；載入 SR 時只保留
   MC68000 定義的 `T/S/I2-I0/X/N/Z/V/C` bits，mask 為 `0xa71f`。
5. 偶數 target 依 restored SR 選 user／supervisor program FC，預取兩 words並令
   PC=target+4；固定 20 clocks。
6. 奇數 target 已保留 SSP+6 與 restored SR，再以 RTE opcode、奇數 target、RTE 後的
   saved PC 進 vector 3；固定 70 clocks，完整 14-byte frame 與 bus 次序沿用 spec 007。

## 驗收與停止線

- 5,000 筆逐筆比較完整 CPU state、RAM、clock 與非 idle bus transaction。
- 本規格只處理 MC68000 format-0 RTE；68010+ format/vector offset word 不在 ST/STF
  第一階段。stack read、vector read、frame write或 handler prefetch backend bus fault
  仍回傳錯誤，不冒稱 double-fault／halt 已完成。
