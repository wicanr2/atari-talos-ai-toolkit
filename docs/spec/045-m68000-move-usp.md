# 045 — Motorola 68000 MOVE USP

狀態：**CONFORMED**（2026-09-05）。

## 範圍與證據

本規格涵蓋 MC68000 的 `MOVE An,USP` 與 `MOVE USP,An`。驗收輸入為 spec 003 固定的
`SingleStepTests/m68000` commit `64b253116a3de04aaac4346c43680960dc9b67e5`：

| 語料 | supervisor／user | SHA-256 |
|---|---:|---|
| `MOVEtoUSP.json.bin` | 1,274／1,226 | `f43a627e07e59c5bfc83f11ef756b1c743d0249186beb7b3f12ea16b66ea7a19` |
| `MOVEfromUSP.json.bin` | 1,293／1,207 | `7dcd639e8f8619b78581940397ba5f07ad4378d879ae3b4fa90e5e2979379947` |

這是 TOS supervisor／user stack 管理的必要 CPU 契約；DM12EN 遊戲組語本身不直接使用，
不能因此省略。其他 SR／CCR move 另立規格。

## typed 行為

1. supervisor mode 的 `MOVE An,USP` 將指定 An 的完整 32 bits 複製到 USP；若 An=A7，
   source 是目前 SSP。`MOVE USP,An` 反向複製；若 An=A7，destination 是目前 SSP。
2. 正常路徑不修改 SR、未選中的 stack pointer 或記憶體，完成 sequential prefetch，
   固定 4 clocks。
3. user mode 不讀寫指定 An／USP，直接以 opcode 位址進 privilege violation vector 8；
   建立 6-byte format-0 frame、切 supervisor、清 trace、讀 handler 並預取，固定 34 clocks。
4. privilege frame、USP／SSP bank 切換及 bus 次序沿用 spec 039 已 CONFORMED 的標準例外契約。

## 失敗模式與驗收

其他 `0x4E6x` 編碼、未實作 opcode、vector／stack／prefetch backend bus fault 必須回傳錯誤。
不改控制協定、素材、存檔或權利邊界。兩份語料共 5,000 筆逐筆比較完整 state、RAM、
clock 與非 idle bus transaction；既有 212,500 筆不得回歸。
2026-09-05 驗收結果為 5,000／5,000 全數通過；全套外部單步語料累計
217,500 筆全數通過。
