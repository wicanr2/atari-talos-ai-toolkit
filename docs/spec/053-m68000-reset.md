# 053 — MC68000 `RESET` 指令

狀態：**CONFORMED**（2026-09-05）。

## 範圍與停止線

本切片只做 `RESET`（`$4E70`）**對 CPU 自己**的效果：privilege 檢查、prefetch 前進與
clock 數。

`RESET` 的作用是把外部 `RESET` 線拉低一段時間，讓周邊裝置重置；**CPU 自身的暫存器、
SR 與記憶體都不因它改變**。所以「周邊被重置了什麼」不屬於本切片——ST 的 I/O 尚未接入
（見 WORKLIST 的「ST／STF I/O memory map」），沒有東西可以被重置，也沒有可對拍的狀態。
等 I/O 逐區接入時，各自的規格要回頭定義自己對 `RESET` 線的反應。

同樣不在本切片：`STOP`、`RTE` 之外的 supervisor 指令、double bus fault 後的
halt／reset 行為，以及 EmuTOS 在 `$FC0088` 之後的開機路徑。

## 平台規格證據

- Motorola／NXP《M68000 Family Programmer's Reference Manual》，
  <https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf>，SHA-256
  `06e4864b78da0e815054cead9326b7ec9914661f240fd39a455f2061ff47c4e8`。
  `RESET` 是 privileged 指令；user mode 執行它產生 privilege violation，
  附錄 B 表 B-1 指定該例外為 vector 8／offset `$020`。
- **外部單步語料**：spec 003 固定的 `SingleStepTests/m68000`
  commit `64b253116a3de04aaac4346c43680960dc9b67e5`，`RESET.json.bin` 2,500 筆。
  分佈是 supervisor 1,233 筆與 user 1,267 筆，兩組的 clock 數各自單一：

  | 前態 | 筆數 | clocks | 行為 |
  |---|---:|---:|---|
  | supervisor | 1,233 | **132** | 只前進 prefetch；SR、D0–D7、A0–A7、RAM 全部不變 |
  | user | 1,267 | **34** | privilege violation → vector 8 |

  clock 直方圖只有 `{34, 132}` 兩個值，沒有第三種，所以本指令沒有資料相依時序。
- 語料首筆 user 案例的 frame 資料釘住 saved PC：`initial PC = $00014B98`，
  寫入的 frame 為 `SR=$061F`、`PC=$00014B94`——即 **opcode 位址**，等於 next-prefetch
  契約下的 `PC − 4`，與 spec 051 的 vector 4 及既有 `MOVE USP` 的 privilege violation
  取值一致。

## typed 行為

1. supervisor mode：唯一的效果是一次順序 prefetch——讀 `PC` 處的 word 補進管線、
   `PC` 加 2，共 **132 clocks**。SR（含 trace bit）、資料與位址暫存器、記憶體皆不變。
2. user mode：以 saved PC ＝ `PC − 4`（opcode 位址）進 vector 8 的標準 6-byte
   format-0 例外，**34 clocks**，與既有 `MOVE USP` 的 privilege 路徑共用同一支
   `enterStandardException`。
3. 外部 `RESET` 線目前沒有觀測者，因此不建模；本切片不得為了「看起來有做事」
   而去清任何記憶體或裝置狀態——那會是憑空發明的行為。

## 驗收與停止線

- `RESET.json.bin` 全 2,500 筆逐筆比較完整 CPU 狀態、RAM、總 clock 與 bus transaction。
- EmuTOS 1.3 UK ROM（`ad64942f5b0f468a08b909827f6cfa2c38e786f853fab407011dc7d6f9c52135`）
  自 reset 起第 10 條指令、220 clocks 到達 `$FC0088` 的 `RESET`，該指令必須執行成功
  並前進到下一條，不再回報 `opcode 0x4e70 is not implemented`。
- 既有 227,500 筆語料與全套 Go 測試不得回歸。
- 通過後**不宣稱 TOS 可開機**：只宣稱開機路徑的下一個停止點往後移動。

## CONFORMED 收據

- 2026-09-05：`RESET.json.bin` 全 2,500 筆通過，狀態、RAM、clock 與 bus transaction
  逐筆相同——supervisor 1,233 筆各 132 clocks、user 1,267 筆各 34 clocks 進 vector 8。
- 2026-09-05，端到端：EmuTOS 1.3 UK ROM 自 reset 起第 10 條指令、220 clocks 到達
  `$FC0088`（與 spec 051 記錄的 Hatari 數字相同），該 `RESET` 執行 132 clocks，
  之後 instructions=11、clocks=352；SR、D0–D7、A0–A6、SSP、USP 全部不變，PC 只前進
  一個 word。
- 227,500 筆既有外部語料與全套 Go 測試在同一次執行中通過。
- **新的停止點**：`$FC008E`（第 12 條指令）讀 `$FA0000` 得 unmapped bus fault。
  那是 cartridge port 區（`$FA0000`–`$FBFFFF`），EmuTOS 在此探測有沒有插卡。
  目前 memory map 不涵蓋該區，且 CPU 只在 `MOVE.W` 來源讀取路徑把 bus fault 轉成
  vector 2，所以錯誤直接往外傳而不是變成例外。**兩件事都要各自立規格**，
  本切片不順手加上去。
