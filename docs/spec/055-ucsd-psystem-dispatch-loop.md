# 055 — UCSD p-System 分派迴圈與 p-code 序列執行

狀態：**CONFORMED**。

## 範圍與證據

規格 054 各自跳進單一常式驗收。本切片補上其上一層：**取指令與分派的循環本身**，
也就是 p-machine 的 fetch-execute。通過之後，Atari Talos 能執行任意 p-code 序列，
而不只是單獨呼叫某支常式——這是把 p-code 當成對拍載體的前提。

素材同 054：SunDog: Frozen Legacy 的 `SYSTEM.INTERP`，SHA-256
`a344edfb07d27cafa3dfda68f1854a76f63a0e89cf2e8229dacf5aa64d603c38`，不進 repository。

分派迴圈在偏移 `$00DE`，就在分派表 `$00EC` 的正前方：

```text
00de:  moveq   #0,d0
00e0:  move.b  (a4)+,d0        ; 取下一個 opcode，p-code IP 前進一個位元組
00e2:  add.w   d0,d0           ; ×2，分派表以 word 為單位
00e4:  move.w  6(pc,d0.w),d7   ; 延伸字在 $00E6，加 6 正好是分派表 $00EC
00e8:  jmp     0(a3,d7.w)      ; 跳進常式
```

`6(pc,d0.w)` 的位移把表的位置寫死在指令裡，這是「分派表就在 `$00EC`」的第二個獨立
證據——054 是直接讀表的內容，這裡是迴圈自己算出來的位址。

`jmp 0(a3,d7.w)` 說明**表項是相對載入基底 `a3` 的偏移，不是絕對位址**。所以直譯器不必
載入在位址 0，測試選擇非零基底也不會讓結果碰巧成立。

執行模型因此是：`a3` 載入基底、`a4` p-code IP、`a5` 迴圈位址（常式以 `jmp (a5)` 回來）、
`a7` 運算元堆疊、`a0` 活動記錄。

## typed 行為

1. 一條 p-code 指令的邊界是「控制權回到 `$00DE`」。短常數族每條耗 **8 條 68000 指令**
   （迴圈 5 條＋常式 3 條）。
2. `a4` 每條 p-code 前進的位元組數等於 opcode 加上它的運算元；`ixa` 的單位元組運算元
   使該條前進 2 個位元組。
3. 運算元堆疊由高位址往低位址成長，先推的值留在較高位址。
4. 序列中的後一條指令看得到前一條留在堆疊上的結果。

## 驗收與停止線

- 四條 `sldc`（5、3、31、0）跑完後堆疊由頂往下是 0、31、3、5，`a4` 前進 4 個位元組，
  共 32 條 68000 指令。
- 混合族序列 `ldl3` / `sldc7` / `ixa $14` 讓迴圈跳進三支不同常式，且後面的指令消費前面的
  結果；結果是「活動記錄第 3 格取出的基底 ＋ 7 × 20 words × 2」。只跑同一種 opcode
  證明不了分派表真的被查了，所以這一條是必要的。
- 負對照：堆疊順序反轉、每條指令數改成 7、`ixa` 運算元改成 `$15`，都確認會讓測試失敗。
- **只有 054 與本規格已驗收的常式可以出現在 p-code 序列裡。** 其餘 opcode 會跳進未驗收的
  常式，可能碰到未映射記憶體而失敗——那是預期的失敗即關閉，不是可以忽略的雜訊。
- **不宣稱 Atari Talos 能執行 SunDog 或任何完整 p-system 程式。** 段落載入、堆積、
  程序呼叫、浮點與字串族都還沒納入；完整 p-machine 另需磁碟、螢幕與輸入，屬 M3。
- 本切片不新增任何硬體行為。
