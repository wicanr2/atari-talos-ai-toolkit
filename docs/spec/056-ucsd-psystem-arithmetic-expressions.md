# 056 — UCSD p-System 的算術、分支與真實邏輯

狀態：**CONFORMED**。

## 範圍與證據

規格 055 讓 p-code 序列跑得動，但只能搬移資料。本切片補上算術、比較與堆疊操作族，
序列因此能表達**實際的運算式**——並且用原版遊戲真正在算的那一條來驗收。

素材同 054：`SYSTEM.INTERP`，SHA-256
`a344edfb07d27cafa3dfda68f1854a76f63a0e89cf2e8229dacf5aa64d603c38`，不進 repository。

新納入的常式（偏移取自分派表）：

| opcode | 偏移 | 語意 |
|---|---|---|
| `$80` `ldcb` | `$050C` | 載入單位元組常數 |
| `$81` `ldci` | `$0514` | 載入 word 常數（運算元 little-endian）|
| `$A2` `adi` | `$0A44` | 整數加 |
| `$A3` `sbi` | `$0A4A` | 整數減，`tos1 − tos0` |
| `$8D` `dvi` | `$0A58` | 整數除 |
| `$8F` `modi` | `$0A6A` | 取餘 |
| `$B0` `equi` | `$0A98` | 相等，結果 1／0 |
| `$B2` `leqi` | `$0AB0` | 小於等於 |
| `$E2` `dup1` | `$0994` | 複製堆疊頂 |
| `$BD` `swap` | `$098C` | 交換頂兩個 |
| `$8A` `ujp` | `$0D0E` | 無條件跳躍 |
| `$D4` `fjp` | `$0D22` | 堆疊頂為 0 時跳 |
| `$F1` `tjp` | `$0D18` | 堆疊頂非 0 時跳 |
| `$78`–`$7F` `sind` | `$06A6`／`$06AE` | 間接載入 word，偏移 0–7 |
| `$A7` `ldb` | `$08A8` | 間接載入 byte |

跳躍的位移相對「位移位元組之後」，不是相對 opcode。`sind` 與 `ldb` 的位址是相對 `a6`
（p-system 記憶體基底）的 16-bit 值。

## typed 行為

1. `ldcb` 的運算元是一個位元組，IP 前進 2；`ldci` 的運算元是 little-endian word，IP 前進 3。
2. 二元運算取 `tos1` 為左運算元、`tos0` 為右運算元：`sldc5` `sldc3` `sbi` 得 2 而不是 −2。
3. 比較運算把布林推成 word 1 或 0。
4. `dup1` 之後堆疊多一個 word；`swap` 不改變堆疊深度。

## 用原版的算式與原版的數值驗收

SunDog 的 `check_exit` 把走路人的 sprite 座標換算成 40×24 的格座標，再用它索引地面圖：

```text
欄     = (捲動x + sprite.x / 步距) mod 40
列     = (捲動y + sprite.y / 步距) mod 24
那一格 = 地面圖基底 + 列 × 20 words × 2
```

三條都寫成 p-code 跑過。**數值不是編出來的**：捲動 `(7,4)`、sprite `(175,120)`、步距 40
都是在原版執行時用除錯器讀出來的，而算出的欄 11、列 7 與同一刻讀到的格座標一致。
所以這一條是拿原版的直譯器、跑原版的算式、餵原版的數值。

| p-code | 運算式 | 結果 |
|---|---|---|
| `07 80 af 80 28 8d a2 80 28 8f` | `(7 + 175/40) mod 40` | 11 |
| `04 80 78 80 28 8d a2 18 8f` | `(4 + 120/40) mod 24` | 7 |
| `81 00 10 04 80 78 80 28 8d a2 18 8f d7 14` | 上一條再 `ixa 20` | `$1118` |

三方一致：Atari Talos 執行原版 68000 直譯器、laanwj/sundog 的獨立 C 直譯器、以及原版
執行時用除錯器讀到的格座標，三者給出同一組值。

## 條件邏輯：地面碼的正規化

有了分支就能表達原版的條件邏輯。`check_exit` 讀出腳下那一格之後做的第一件事是
「大於 15 就減 16」——那 16 是 `draw_city_map` 繪圖時加上的視覺變體偏移：

```text
dup1 / sldc15 / leqi / tjp +2 / sldc16 / sbi
```

| 輸入 | 輸出 | 意義 |
|---:|---:|---|
| 5 | 5 | `check_exit` 特地為它開的那條 `or` |
| 15 | 15 | 邊界，不減 |
| 16 | 0 | 邊界，要減 |
| 35 | 19 | Drahew 的倉庫槽位 |
| 36 | 20 | 門表上界，等於 `check_building` 跳表的 `max` |

## 驗收與停止線

- 11 組單一運算式加 3 組座標換算，堆疊內容、深度與 IP 位移全查。
- 5 組跳躍（`ujp`、`fjp` 真假兩路、`tjp` 真假兩路）、4 組間接載入、5 組地面碼正規化。
- 期望值另由 laanwj/sundog 的獨立 C 直譯器確認（外部 oracle，本 repository 不連結、
  不移植也不依賴它）。
- 負對照：`sbi` 的運算元順序反轉、座標換算的步距從 40 改成 32、`dup1` 只留一個值，
  三組都確認會讓測試失敗。
- **除以零、負數的除法與取餘、溢位邊界都不在本切片。** 那幾條會走進錯誤路徑或牽涉
  MC68000 `DIVS` 的符號約定，需要各自的證據。
- 本切片不新增任何硬體行為，也不擴大 054／055 的停止線——仍然不宣稱能執行 SunDog
  或任何完整 p-system 程式。
