# 058 — UCSD p-System 的布林運算：真假住在 bit 0

狀態：**CONFORMED**。

## 範圍與證據

規格 056 讓 p-code 能算算術與比較。本切片補上布林族 `land`／`lor`／`bnot`，
並釐清一件會改變程式判讀的事：**p-system 的真假不是「非零」，是最低位元**。

素材同 054、056：`SYSTEM.INTERP`，11,776 bytes，SHA-256
`a344edfb07d27cafa3dfda68f1854a76f63a0e89cf2e8229dacf5aa64d603c38`，
原版磁碟檔案，**不進 repository**；測試以 `TALOS_UCSD_INTERP` 指向存放目錄。

新納入的常式（偏移取自分派表 `$00EC`）：

| opcode | 偏移 | 68000 | 語意 |
|---|---|---|---|
| `$A1` `land` | `$0A02` | `move.w (a7)+,d0` / `and.w d0,(a7)` | 位元 AND |
| `$A0` `lor` | `$0A08` | `move.w (a7)+,d0` / `or.w d0,(a7)` | 位元 OR |
| `$9F` `bnot` | `$0A12` | `not.w (a7)` / `andi.w #1,(a7)` | 翻 bit 0 |

已納入的 `fjp`（`$0D22`）與 `tjp`（`$0D18`）在這裡補上一條先前沒有寫明的性質：
兩支都是 `move.w (a7)+,d0` / `btst #0,d0` / `beq`（或 `bne`），**測的是 bit 0**。

## typed 行為

1. `land` 與 `lor` 是 word 的位元運算，不是邏輯運算：`2 and 1` 得 0（邏輯運算會得 1），
   `2 or 4` 得 6（邏輯運算會得 1）。
2. `bnot` 是 `(~x) & 1`：`not 2` 得 1、`not 7` 得 0，整個 word 不取補數。
3. `fjp` 在 bit 0 為 0 時跳、`tjp` 在 bit 0 為 1 時跳。因此 **8 是假、9 是真**。
4. 三者都不改變堆疊深度以外的狀態，結尾一律 `jmp (a5)` 回分派迴圈。

比較運算（`equi` 等，規格 056）推出的是 1 或 0，所以在「比較 → 布林運算 → 分支」
這條常見的鏈上，位元與邏輯的差別看不出來。差別只在其中一個運算元不是 0/1 的時候
出現——而那正是下面那段原版程式碼的情形。

## 用原版的判斷式驗收

SunDog 的 `XSTARTUP:0x31` 決定新遊戲開局時船上的初始損壞長什麼樣。段內 `0x1acb`：

```text
sldl4 / sldc0 / equi      ; 壞掉的欄 == 0（control node）
sldc0 / scxg4 0xb / lor   ; 位元或上一次 random()
fjp 0x1ae3                ; 結果的 bit 0 為 0 → 寫替代零件、列狀態 3
```

`random()` 是 `MAINLIB:0x0b` 的 LCG，回傳 `abs(seed / 4)`，值域 0–8191。

**把 `lor` 當邏輯或、把 `fjp` 當「整個 word 為零才跳」來讀，這個條件會幾乎永遠成立**，
列狀態 3 幾乎不可能出現。SunDog remake 專案的三次獨立新遊戲實測不是這樣：72 個列狀態
裡有 8 個是 3。讀成位元或加 bit 0 之後，條件為假的機率是
`P(欄 ≠ 0) × P(random 為偶) = 3/4 × 1/2 = 3/8`，與實測的 8/23 ＝ 34.8% 相符。

`TestUCSDInterpNewGameDamageBranch` 把那段判斷式在 Atari Talos 上跑出來，
四種組合（欄是不是 0 × 亂數的奇偶）涵蓋整張真值表，走哪一條由堆疊深度判定。
跨段呼叫 `scxg4 0xb` 不在本切片範圍，測試以 `ldcb` 給定的常數取代 `random()` 的回傳值；
被驗收的是**這個判斷式怎麼判**，不是亂數怎麼產生。

## 驗收與停止線

- 分派表的定位（`$A1`→`$0A02`、`$A0`→`$0A08`、`$9F`→`$0A12`）由
  `TestUCSDInterpDispatchTableBooleanRoutines` 直接讀表確認，不經過 CPU。
  少了這一條，執行測試會同時假設定位與語意都對，兩邊一起錯就看不出來。
- 負對照做過：把「`2 or 4` = 6」改成邏輯或的 1、把「fjp 把 8 當成假」改成「當成真」，
  兩條都確認會失敗。
- **本切片不宣稱 Atari Talos 能執行 SunDog**。它只證明這三支常式加上兩支跳躍常式
  在 CPU 上跑出與人工反組譯一致的結果，並且那個結果能解釋原版的實測分布。
- 亂數產生器本身（`MAINLIB:0x0b`）與跨段呼叫（`scxg`）不在這裡；
  段落載入、字串、集合、浮點也都還沒納入。
- 本切片不新增任何硬體行為，因此不需要硬體規格；它是驗收語料的契約。
