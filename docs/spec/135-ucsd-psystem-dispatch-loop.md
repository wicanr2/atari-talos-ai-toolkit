# 135 — UCSD p-System 分派迴圈與 p-code 序列執行

狀態：**CONFORMED**。

## 範圍與證據

規格 134 各自跳進單一常式驗收。本切片補上其上一層：**取指令與分派的循環本身**，
也就是 p-machine 的 fetch-execute。通過之後，Atari Talos 能執行任意 p-code 序列，
而不只是單獨呼叫某支常式——這是把 p-code 當成對拍載體的前提。

素材同 134：SunDog: Frozen Legacy 的 `SYSTEM.INTERP`，SHA-256
`a344edfb07d27cafa3dfda68f1854a76f63a0e89cf2e8229dacf5aa64d603c38`，不進 repository。

分派迴圈在偏移 `$00DE`，就在分派表 `$00EC` 的正前方：

```text
00de:  moveq   #0,d0
00e0:  move.b  (a4)+,d0        ; 取下一個 opcode，p-code IP 前進一個位元組
00e2:  add.w   d0,d0           ; ×2，分派表以 word 為單位
00e4:  move.w  6(pc,d0.w),d7   ; 延伸字在 $00E6，加 6 正好是分派表 $00EC
00e8:  jmp     0(a3,d7.w)      ; 跳進常式
```

`6(pc,d0.w)` 的位移把表的位置寫死在指令裡，這是「分派表就在 `$00EC`」的第二個獨立
證據——134 是直接讀表的內容，這裡是迴圈自己算出來的位址。

`jmp 0(a3,d7.w)` 說明**表項是相對載入基底 `a3` 的偏移，不是絕對位址**。所以直譯器不必
載入在位址 0，測試選擇非零基底也不會讓結果碰巧成立。

執行模型因此是：`a3` 載入基底、`a4` p-code IP、`a5` 迴圈位址（常式以 `jmp (a5)` 回來）、
`a7` 運算元堆疊、`a0` 活動記錄。

## typed 行為

1. 一條 p-code 指令的邊界是「控制權回到 `$00DE`」。短常數族每條耗 **8 條 68000 指令**
   （迴圈 5 條＋常式 3 條）。
2. `a4` 每條 p-code 前進的位元組數等於 opcode 加上它的運算元；`ixa` 的單位元組運算元
   使該條前進 2 個位元組。
3. 運算元堆疊由高位址往低位址成長，先推的值留在較高位址。
4. 序列中的後一條指令看得到前一條留在堆疊上的結果。

## 分派表的形狀

256 個 opcode 分派到 **107 支常式**，這張表就是這份直譯器能力範圍的完整地圖：

| 常式 | opcode | 內容 |
|---|---|---|
| `$0304` | `$40`–`$5F`、`$AA`、`$AF`、`$F5`–`$FF`，共 **45 個** | 無效 opcode，首指令是 `moveq #11,d0`——錯誤碼 11 |
| `$00D8` | `$00`–`$1F` | 短常數（134 已驗收）|
| `$0534` | `$20`–`$2F` | 載入區域變數 1–16（134 已驗收）|
| `$0554` | `$60`–`$67` | 取區域變數位址 1–8 |
| `$057C` | `$68`–`$6F` | 存入區域變數 1–8 |
| `$0952` | `$D7` | 陣列索引（134 已驗收）|
| `$00DE` | `$9C` | **指回迴圈起點**，等於 NOP |

`$0554` 是 `subi.w #$BE,d0` / `add.l a0,d0` / `sub.l a6,d0` / `addq.w #8,d0`：先算出那一格
的主機位址，再減掉 `a6`。**`a6` 是 p-system 記憶體基底**，所以推上堆疊的是 p-system 位址
而不是主機位址——這一條決定了 p-code 看到的位址空間長什麼樣。

## 驗收與停止線

- 四條 `sldc`（5、3、31、0）跑完後堆疊由頂往下是 0、31、3、5，`a4` 前進 4 個位元組，
  共 32 條 68000 指令。
- 混合族序列 `ldl3` / `sldc7` / `ixa $14` 讓迴圈跳進三支不同常式，且後面的指令消費前面的
  結果；結果是「活動記錄第 3 格取出的基底 ＋ 7 × 20 words × 2」。只跑同一種 opcode
  證明不了分派表真的被查了，所以這一條是必要的。
- `sldc21` / `sstl1` / `ldl1` 的存取往返：值落在記憶體 `frame+8+1×2` 上，再讀回堆疊。
  這條同時擋掉「兩支常式互相自洽卻都算錯位址」——期望值直接對記憶體查，不只對堆疊查。
- `slla1`–`slla8` 推出的位址是 `(a0−a6) + 8 + n×2`，即 p-system 位址。
- `$9C` 兩條加一條 `sldc5`：IP 前進 3 個位元組而堆疊只多一個值。
- 分派表形狀：107 支常式、45 個無效 opcode、`$9C` 指回迴圈、錯誤常式首指令是 `moveq #11,d0`。
- 負對照：堆疊順序反轉、每條指令數改成 7、`ixa` 運算元改成 `$15`、常式支數改成 106、
  活動記錄偏移改成 6、往返檢查錯的記憶體格——六組都確認會讓測試失敗。
- **只有 134 與本規格已驗收的常式可以出現在 p-code 序列裡。** 其餘 opcode 會跳進未驗收的
  常式，可能碰到未映射記憶體而失敗——那是預期的失敗即關閉，不是可以忽略的雜訊。
- **不宣稱 Atari Talos 能執行 SunDog 或任何完整 p-system 程式。** 段落載入、堆積、
  程序呼叫、浮點與字串族都還沒納入；完整 p-machine 另需磁碟、螢幕與輸入，屬 M3。
- 本切片不新增任何硬體行為。

## 與第二個實作的對拍

測試的期望值不只由本專案自己算出。同一段 p-code 另外餵給 laanwj/sundog 的
`psys_interpreter.c`——那是同一套 p-machine 的獨立 C 重寫，與原版 68000 直譯器沒有共同
的實作來源。六組 p-code 兩邊逐字相同：

| p-code | 意義 | 兩邊的結果 |
|---|---|---|
| `05 03 1f 00` | 四條短常數 | 堆疊 `[0, 31, 3, 5]`，IP +4 |
| `22 07 d7 14` | `ldl3` / `sldc7` / `ixa $14` | 堆疊 `[4376]` ＝ `$1118` |
| `15 68 20` | `sldc21` / `sstl1` / `ldl1` 往返 | 堆疊 `[21]`，區域變數 1 ＝ 21 |
| `60` | `slla1` | 堆疊 `[32778]` ＝ `$800A` ＝ `mp + 8 + 1×2` |
| `9c 9c 05` | 兩條 NOP 加一條短常數 | 堆疊 `[5]`，IP +3 |
| `d7 81 00` | `ixa` 的兩位元組變長運算元 | 堆疊 `[5120]` ＝ `$1400` |

**Atari Talos 不連結、不移植也不依賴那份程式碼。** 它與 Hatari 的角色相同：外部 oracle，
用來確認期望值不是單方面算出來的。跑 oracle 的工具在 SunDog remake 專案
（`tools/psys_oracle.c`，MIT 授權的直譯器加一層最小執行狀態），本 repository 不含它。

對拍排除的是「其中一邊理解錯了」，不排除「兩邊照同一份錯誤文件寫」。這裡一邊是 1985 年
出貨的原版機器碼，不存在照文件寫的可能，所以那個風險只落在 C 重寫那一側——而那正是
Atari Talos 這側要執行**原版位元組**、而不是自己重新實作 p-machine 的理由。
