# 143 — 滑鼠按鍵的封包與 GEM 的點選語意

狀態：**CONFORMED**。

## 範圍

規格 142 把左右鍵的位元放進封包表頭，依據是兩份 IKBD 協定文件的位元佈局。
本切片把那個位元位置**從文件推論升級成行為驗證**：按下與放開各發一個封包，
交給 EmuTOS 的桌面去反應，看它認的是哪一顆。

**不在本切片**：雙擊、拖曳、鍵盤掃描碼、joystick、`$07` 的 button-as-key
與 absolute report 兩個位元。

## 證據

- **已確認（Atari IKBD 協定文件）**：相對模式下，「依 mouse key mode，
  按鍵按下或放開也會產生滑鼠位置回報」。所以一次點擊在線上是兩個封包，
  位移都是零，差別只在表頭的按鍵位元。
- **已確認（EmuTOS 1.3 固定 ROM，端到端）**：游標移到 `DISK A` 圖示上之後——
  - 送 `$FA 00 00`（左鍵按下）→ 圖示與標籤反白，1,169 個像素變動，
    範圍 (0,11)–(72,51)，`DISK B` 完全不動。
  - 再送 `$F8 00 00`（放開）→ 畫面**回到按下之前**，變動 0 個像素。
    這是 GEM 對「按住太久又沒有移動」的取消路徑，同時證明放開的那個封包確實
    送到了、也被處理了。
  - 換成短按（按下與放開之間只跑 40,000 條指令）→ 圖示**維持反白**，
    相對於未點擊時變動 1,140 個像素，範圍 (0,17)–(71,50)。這就是 GEM 的點選。
  - 同一個位置送 `$F9 00 00`（右鍵按下）與放開 → **兩次都是 0 個像素變動**。
    桌面完全不理右鍵。
- 因此表頭的 **bit 1 就是 GEM 會反應的那一顆按鍵（左鍵）**，bit 0 是右鍵——
  與規格 142 引的位元佈局一致，而且這次不是靠文件說的。

## typed 行為

1. 按鍵狀態改變時發一個相對位置封包，位移為零，表頭帶新的按鍵狀態
   （`$F8 | 左<<1 | 右`）。位移與按鍵同時改變時只發一個封包，兩者都帶上。
2. 按鍵狀態沒變、位移也是零時不發封包（規格 142 已有）。
3. `QueueMouseButtons(left, right)` 是只送按鍵的入口，等同位移為零的
   `QueueMouseMotion`。

## 驗收與停止線

- synthetic：按下、放開各一個封包且位移為零；連送兩次相同狀態只發第一個。
- 固定 ROM：上面那四段（長按反白、放開還原、短按維持反白、右鍵完全沒反應）。
- **不宣稱**雙擊、拖曳與拖放已建模；也不宣稱右鍵在別的 GEM 程式裡沒有用途——
  這裡只證明 EmuTOS 1.3 的桌面在圖示上不理它。
