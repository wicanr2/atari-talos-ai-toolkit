# 144 — YM2149 的聲音暫存器與 R7 的讀改寫

狀態：**CONFORMED**。

## 範圍

到規格 143 為止，PSG 只建模了 R7（混音／port 方向）與 R14（port A），而且是
把它們釘在開機路徑上出現過的**固定值**。第一次按鍵就打破了那個假設：
EmuTOS 會彈一聲按鍵音。

本切片接上 R0–R13（聲音暫存器），並把「R7 等於 `$C0`」這個假設換成
「R7 的兩個 port 方向位元是輸出」。

**不在本切片**：真的產生聲音（本模型不輸出音訊，只保存暫存器值）、
R15（port B，並列埠資料）、envelope／tone 產生器的時序、`Dosound` 的排程。

## 證據

- **已確認（EmuTOS 1.3 固定 ROM，探針一次看完整串）**：在桌面上按一個鍵，
  ROM 依序寫出

  ```text
  R0  <- $3B     R1  <- $00     R2  <- $00     R3  <- $00
  R4  <- $00     R5  <- $00     R6  <- $00
  讀 R7 -> $C0   R7  <- $FE
  R8  <- $10     R13 <- $03     R11 <- $80     R12 <- $01
  ```

  也就是：設 A 聲道的音高、把 B／C 與雜訊關掉、**R7 從 `$C0` 變成 `$FE`**、
  A 聲道的音量改用 envelope（R8 bit 4）、設 envelope 形狀與週期。
  `$FE` 的高兩位仍是 `$C0`——ROM 是**讀改寫**，只動混音位元，
  port 的方向位元原封不動。
- **已確認（YM2149 公開規格）**：R7 的 bit 6／bit 7 是 port A／port B 的方向
  （1 = 輸出），bit 0–5 是三個聲道的 tone／noise 開關。所以 port A 能不能寫，
  只跟高兩位有關，跟混音位元無關。

## typed 行為

1. port 方向設好之後（R7 的高兩位是 `$C0`），select 可以指到 R0–R13，
   data 寫入直接存進對應的暫存器，讀回傳回目前的值。**只保存值，不產生聲音。**
2. R7 的寫入若把任一個 port 方向位元清掉，**失敗即關閉**——那會讓 port A
   變成輸入，還沒建模。
3. R15 與 15 以上的 select 值仍然失敗即關閉。
4. 所有以 port A 為前提的規則（drive 選擇、`flopvbl()`、媒體確認）改看
   `psgPortsAreOutputs()`，不再要求 R7 整個位元組等於 `$C0`。
5. 「選 R14」的規則**真的會把 `psgRegisterSelect` 設成 14**。先前那些規則
   靠「前提已經是 14」蒙混過去，在沒有別的東西碰 PSG 的時候剛好等價；
   一旦按鍵聲選過 R12，讀回就會拿到 R12 而不是 port A。

## 驗收與停止線

- synthetic：R0–R13 寫入與讀回、R7 讀改寫保留方向位元、把方向位元清掉
  fail-closed、R15 fail-closed、選 R14 之後讀回拿到的是 port A。
- 固定 ROM：按鍵之後上面那整串寫入都被接受，且接著的 `flopvbl()` 輪詢照常走
  （規格 145 的收據涵蓋）。
- **不宣稱 PSG 的聲音已建模**：沒有音訊輸出、沒有 envelope 時序、
  沒有 `Dosound` 的排程。這裡做的只是「暫存器寫得進去、讀得回來，
  而且不會把 port A 的模型帶壞」。

## CONFORMED 收據

- 2026-09-06：synthetic 與固定 ROM 都通過。原本有 **15 處**把 R7 釘在 `$C0`，
  全部換成方向位元的檢查；6 條「選 R14」的規則補上實際的 `psgRegisterSelect`
  寫入。
- 兩支既有測試的斷言被本片取代：`TestPSGFixedBootPortWrites` 與
  `TestSTYM2149ParallelPortStrobeInit` 原本拿 R0／R13 當「還沒建模」的例子，
  現在改用 R15。
